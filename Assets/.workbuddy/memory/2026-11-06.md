## 修复两个 bug（用户截图反馈）

### 1. 音标重叠（zone 截图：ə 和 n 叠成一个字）
- 根因：WordPhonicsMap.json 里 zone 的 əʊ phoneme positions=[1,3]（跨 o..e），而 n_back positions=[2]——两块区间重叠。WordTrailTyping.UpdatePhonicsOverlay 直接按 min/max 展开成两个 chunk，下划线和音标 TextMesh 叠画在 n 附近。
- 修复：UpdatePhonicsOverlay 里按 start 排序 + 相邻块区间重叠合并（count 取并集、sound 拼接，əʊ+n_back→əʊn_back）；WordPhonicsOverlay.Build 的文件键退级逻辑从"只保留开头 ASCII 字母"改为"按第一个 _ 或 / 截断"（否则 əʊn_back 会因 ə 非 ASCII 变空串）。

### 2. 手部裂开（burst 截图，按 B 时右手被撕开）
- 根因：TypingHands 手部左右半幅按 SeamData 折线缝切分。hl_B 的缝数据坏了：行 12-47 常数 1300，其中行 12-21（y240-420）直接切穿右手中/无名指实心区（实测 alpha 135-167）；行 47→48 从 1300 跳到 820 又一条斜切。左右组各自缩放/锚定/下压（UpdateHandDip），缝穿内容处即裂开。其他层实测 0/53 行穿模，仅 hl_B 坏。
- 修复：hl_B 缝条目用 alpha 图 Dijkstra（2px 网格，走廊约束）重算为 1026×21,1014,1002×31，全程透明走廊，仅伸指软边 alpha≤132 极淡擦碰。经验：伸指层（手指触到另一手软边）会让连通域法失效，以后出现同类裂手先查 SeamData 对应层是否穿模（±12px alpha>40 校验脚本思路）。

## 追加：手指上"莫名白线"（用户第二次反馈，按 C 时右手掌/指部竖向白线）
- 根因同源：SeamData 除 hl_B 外还有 hl_C/hl_X/hl_Z 三层是坏的——hl_C 行 36-37=990 切穿右手拇指（alpha 153）、行 20-24 切 952-996 实心区；hl_X 行 22=1008 切 alpha169；hl_Z 行 31-34 切 alpha 149-164、行 48=820 斜切。共同规律：**下排键 Z/X/C/B 的伸指（及右手拇指）与另一手软边相触，连通域缝线生成器全部失效**。
- 修复：4 层全部用 alpha 图 Dijkstra 重算（2px 网格，走廊 650-1450，代价=±2px 硬 alpha+0.3×±12px 软 alpha——第一版纯 ±12px 窗口代价会把窄指缝和实心手指算成同价，导致路径宁可切手指，切记）。终检（±2px 贴身、9 采样/段）：hl_X 完全干净，hl_B 残 1 点 a93、hl_C 2 点 a123、hl_Z 2 点 a118（均为半透明软边，视觉不可见）；hl_I/hl_Enter 各 1 点 a49/a106 为原有轻微擦碰，未动。
- 教训：缝线穿模校验必须用"贴身 ±2px"判实穿、±12px 只作软参考；离线生成器迟早要换成 Dijkstra 方案。

## 追加2：手腕处"多余白色线条"（第三次反馈，C 键下压时两手腕间隙的斜向亮带）
- 真正根因（前两轮只修了表层）：**新版手部素材带一层 alpha≈36 的白色光晕**（alpha 直方图 32-47 档 3.4 万采样、RGB 241），光晕横跨缝线；而左右组各自独立缩放锚定（sL=3*keyPitch/左手虎口跨度、sR 同理，F/J 精确对位），缝线两侧变换必然有偏差 → 光晕在缝处叠加成亮带/裂开成暗带。旧 hl_C 行 47→48 = 998→820 的 178px 大跳变正好对应用户截图亮带的宽度与斜向。之前的"缝线穿模"只是问题的一部分，光晕楔形才是亮带主源。
- 修复：BuildHalfMesh 从 2 列顶点改 3 列——左半 [0|split|split+80]、右半 [split|split+80|1960]，缝线处 80px 互补顶点色 alpha 羽化（左 1→0、右 0→1，和恒 1），δ<80px 的变换偏差都不再出硬边。材质 URP/Particles/Unlit 吃顶点色，无需改 shader。
- 教训：美术 alpha 直方图必须先看再定阈值——手身 alpha=170、光晕 36，用 >40 当"内容"判据会把光晕当空气；半透明大色块（光晕/阴影）跨分割线时，硬分割必然出楔形伪影，要羽化。
